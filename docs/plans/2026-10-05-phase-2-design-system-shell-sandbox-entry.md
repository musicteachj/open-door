# Phase 2: Design System, Shell, and Sandbox Entry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking. **Project rule:** never commit, push, or open a PR without
> the owner's explicit OK for that action (see `CLAUDE.md`). Every "Propose the commit" step stops
> and waits.

**Goal:** A visitor opens Open Door, picks a persona, and lands in a private sandbox, inside an app
that looks and behaves like the approved Claude Design screens. They can switch persona, sign out,
find anyone in the directory, and see exactly the profile fields their role allows. The assistant
isn't connected yet: asking a question gives a fixed reply.

**Architecture:**
- **The API** gains directory search, filters, and counts, and an OpenAPI schema that describes its
  real error bodies.
- **The theme.** The web app turns the exported design tokens into a Tailwind v4 theme, and two
  tests keep it in step with the export.
- **The network.** One fetch wrapper is the generated client's only way to the network: it sends
  the CSRF token and throws a typed error.
- **State.** TanStack Query holds server state under fixed retry rules, and a persona switch or
  sign-out clears all of it. React Router guards the signed-in pages with `/me`.
- **Components** are shadcn/ui primitives and product components restyled to the tokens, shown in
  every state in a dev-only gallery.
- **Testing.** Playwright drives the built app against the real API in a new CI job, with axe on
  every screen and a 390 px check. A local capture report sets each design screenshot beside the
  build.

**Tech stack:**
- **API:** FastAPI, SQLAlchemy 2.1, and pytest against Postgres 17, as in Phase 1.
- **Web app:** React 19, TypeScript 6, Vite 8, Tailwind 4, shadcn/ui on the unified `radix-ui`
  package, React Router 7, TanStack Query 5, Zustand 5, and Lucide. The client is generated by
  Orval.
- **Tests:** Vitest 5 with Testing Library and MSW 2, and Playwright with `@axe-core/playwright`.

## How this plan is written

**This plan gives outlines, not finished code.** Phase 1's plan pasted pre-run code into every
step. This one doesn't: building a phase once to plan it and again to ship it costs a lot and
gains little. The owner decided this on 2026-10-05.

Each task gives:
- the files
- the tests to write first, and what each must prove
- the interfaces that later tasks depend on
- notes on the traps already known

The implementer writes the code test first: they watch each test fail for the right reason, then
make it pass. Problems are solved during the build and recorded under
[Changes made during execution](#changes-made-during-execution).

**Known traps** come from a short trial build of Stages 1–4 during planning, which was then
deleted. They are written into the tasks as "Known:" notes. The versions named are the ones that
resolved on 2026-10-05.

**Where markup comes from.** For the components and screens, the design is the specification:
the sketches in [`../design/system/components/`](../design/system/components/), the screens'
`notes.md`, and the screenshots. The capture report and the owner's review settle the markup.

  planted bug for each behavior that could fail silently, such as a tooltip that opens for any

  names the effort level for the next session (`medium`).
- **`docs/BACKLOG.md` items** are deleted when done, and recorded in the changelog.
- **`docs/DATA-INVENTORY.md`** changes in the same task as the data it describes.

### Task 3: Search and filters in the directory query

**Files:** `people/queries.py`, `tests/integration/test_directory_queries.py` (new), and a
`seeded_sandbox` fixture in `tests/integration/conftest.py`. Merge into the conftest; never replace
it.

**Interface:**

```python
@dataclass(frozen=True)
class DirectoryFilters:
    q: str | None = None
    location_id: UUID | None = None
    department_id: UUID | None = None
    team: frozenset[UUID] | None = None  # None: no team filter; empty: matches no one


async def list_directory(session, *, limit: int, after: DirectoryCursor | None,
                         filters: DirectoryFilters = DirectoryFilters()) -> DirectoryResult: ...
```

- [ ] **Tests first,** against a seeded sandbox:
  - a search for part of a name, for a title, and for an email
  - case doesn't matter
  - `%` and `_` match only themselves
  - each filter alone, and filters combined
  - the team filter, with an empty set matching no one
  - filtered paging across a cursor neither repeats nor skips anyone
- [ ] **Implement:**
  - `q` matches `given_name || ' ' || family_name`, `title`, or `work_email`, with `ILIKE` and an
    explicit `ESCAPE '\'` after escaping `\`, `%`, and `_`.
  - The keyset order stays `(family_name, given_name, id)`.
  - **Known:** once the conftest imports `DirectoryFilters`, the test-first failure is a conftest
    import error, not an assertion. That's expected.

### Task 12: `apiFetch`, the generated client's only way to the network

**Files:** `src/lib/api-fetch.ts` (and its test), `orval.config.ts`, `src/test/msw.ts`, and
`src/test/setup.ts`. Delete `App.tsx` and `App.test.tsx`: the health demo goes, and the router
replaces it.

**Interface:**
`apiFetch<T>(url, init): Promise<T>`, and
`class ApiError extends Error { status; problem: Problem | null; requestId: string | null }`.
The file also exports `ErrorType<T>`, so every hook's `error` is an `ApiError`.

- [ ] **Tests first,** with MSW:
  - `X-CSRF-Token` is sent on POST, PUT, PATCH, and DELETE, never on GET, and nothing is sent when
    there is no cookie.
  - A changed cookie is used on the next call.
  - The JSON content type is set when there is a body.
  - A non-2xx response throws `ApiError`, with `X-Request-ID` and the problem body.
  - A body without a string `title` and a numeric `status` gives `problem: null`, as with the
    health 503 or a proxy's 502.
- [ ] **Orval:**
  - `override.mutator` points at `apiFetch`.
  - Set `fetch.includeHttpResponseReturnType: false`, so a call returns the body itself, now that
    a failure throws.
  - `apiFetch` lives in `src/lib/`, because Orval's `clean` empties `src/api/`.
- **Known:** jsdom enforces the `__Host-` rules, so a test cookie needs `Secure` and `Path=/`.
